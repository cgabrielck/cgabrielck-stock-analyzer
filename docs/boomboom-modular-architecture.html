BoomBoom Modular Architecture (M1–M13)

ADR-003 + Addendum A Accepted · M1–M13 DAG · dual-clock H1–H3 · IntentStore · Proposal→Approve→Merge · 2026-10-21

1 · Protected core — M8

gates · position sizer · mandate · kill switch · audit. Fail-closed. Does not depend on M7. No model-supplied size. Semantic changes = highest review.

2 · Soft judgment — M7

Closed veto reason codes + conviction tier only. Never triggers entries from headlines alone. Never calls place_order. Must beat rules-only E on shadow before live.

3 · User-visible desk — M4 / M10 / M11

TradingView-like charts & indicators, every trade log traceable to the user, remote FastAPI desk UX (mini-Futu). Reference SignalCards via M5 (schema still planning). Streamlit = lab/legacy, not the product surface.

Dual-clock · H1–H3

H1 (~1s): kill / exits / consume IntentStore — no LLM.
H2 (5–15s): order status / light reconcile — no LLM.
H3 (minute/bar): M6+M7 write IntentStore (LLM allowed).
Proposal governance is a separate path — not mixed into live intents.

IntentStore (L1) vs OrderStore (L2)

H3 writes Intent v0 (side / stop / conviction_tier / expiry). H1 consumes unexpired intents through M8 sizer. Existing OrderStore is the L2 order ledger — not IntentStore. Intent v0 forbids qty / notional / broker ids / fills.

Proposal → Approve → Merge

Learn + digest → HarnessProposal vN → present on Desk → explicit user Approve → M13 checklist → M12 Merge / Rollback. L2 (mandate / kill / risk% / live) never auto-merges. Unapproved Proposal is not an Intent.

L1 vs L2

L1 may auto: intents, conviction, watchlist, closed-list veto toggles (still sized by M8 before any order).
L2 constitution only via Approve+Merge: mandate, kill, risk caps, strategy defaults, live flag, mandatory stop rules.

lab/advisory_debate ≠ product M7

backend/lab/advisory_debate.py is a lab Bull/Bear/Risk memo. It is not product M7 and must not wire to OrderManager / M9. Product M7 = closed veto + conviction + digest-for-Proposal only.
